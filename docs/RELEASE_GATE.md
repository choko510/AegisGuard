# 出荷品質ゲート（P10-03）の実測記録

**結論：ゲートは未達です。** 下は、利用者の許可を得てこの開発用Windows 11（隔離VMではない、日常使用のPC）で実施できた範囲の実測です。CIの成功やこの1台の数値をもって「本番対応」「リアルタイム保護完成」とは言いません。

- 測定日：2026-11-06（JST）
- 機材：AMD Ryzen 7 7700X（8コア）、メモリ31.1GB、Windows 11 Pro ビルド26220、電源プラン「高パフォーマンス」、AC電源（バッテリーなし）
- Microsoft Defender：製品 4.18.26100.4、署名 1.463.140.0、リアルタイム保護 有効、改ざん防止 有効
- Sysmon：**未導入**（導入はドライバーとシステム設定の変更を伴うため行っていない）
- 実行権限：一般ユーザー（管理者ではない）。リリースビルド。

## 測定結果

| 項目 | 条件 | 結果 |
|---|---|---|
| 静的スキャン（合成コーパス） | 1,500ファイル、3回 | 1回目 8.2秒（コールドキャッシュ・新しいexeへのDefenderの検査を含む）、2・3回目 約1.0秒、CPU 0.8〜0.9秒、ピークワーキングセット 約47MB |
| 静的スキャン（実ファイル） | `C:\Windows\System32` 直下 4,490ファイル | 50.4秒、CPU 34.6秒、ピーク 97MB。**PEごとのAuthenticode検証（主に署名カタログの照合）が大半**。大量の実行ファイルを対象にする場合の主要コスト |
| GUI（アイドル） | 起動10秒後から60秒、サービスへの5秒ごとの問い合わせあり | CPU 0.23秒（約0.4%）、ワーキングセット115MB（主に日本語システムフォント） |
| 常駐サービス（console） | 10秒間隔、Defender Operational・Application・Sysmon（未導入） | 初回の取り込み30秒でCPU 2.8秒。**定常180秒でCPU 0.28秒（約0.16%）**、ワーキングセット27MB、Defender 8,137件・Application 30,968件（実際の件数と一致）、gap なし、スプール18.6MB |
| Defender設定の不変 | 測定の前後で `Get-MpPreference` を比較 | **差分は PowerShell のセッション情報 `RunspaceId` のみ。Defenderの設定値はすべて同一** |

### 測定中に見つけて直した不具合

サービスの初回測定で、ログの**最後のイベント**から再開すると「カーソル喪失」と誤判定し、毎回最古から読み直していた（Application を20.6万件・Defender を10.6万件と重複保存、偽の gap、CPU 1コアの約11%、スプール151MB）。P2-01 以来の不具合で、CIでは再現していなかった。修正後の値が上の表である（修正PRを参照）。

## 未決定の性能予算

ハードウェア別の合格閾値（ms・MB・%）は未設定のままです。上の値は「この機材での1回の観測値」であり、予算ではありません。少なくとも、標準的なノートPC（バッテリー駆動）と低スペック機での同じ測定、Sysmonを導入した状態での24時間の測定が必要です。
