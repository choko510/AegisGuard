# P1-01 YARA-X統合方式の決定記録

> 決定日: 2026-11-05 / 対象: YARA-X `1.22.1`（crates.io、2026-10-26公開、BSD-3-Clause、`rust-version = 1.95.0`）
> 関連: [ADOPTION_MATRIX.md](ADOPTION_MATRIX.md)、[IMPLEMENTATION_ROADMAP.md](IMPLEMENTATION_ROADMAP.md) P1-01〜P1-03、調査 [yara-rust-api](../results/yara-x/yara-rust-api.md)・[yara-rules-maintenance](../results/yara-x/yara-rules-maintenance.md)

## 決定

**公式crateを任意のcargo feature `yara`（既定OFF）として本体に組み込む。** 既定ビルドは `rust-version = 1.85` を維持し、`--features yara` のビルドだけがRust 1.95以上を要求する。旧版（v1.0.0、MSRV 1.85）への固定と、外部CLI（`yr`）の子プロセス実行は採用しない。

| 方式 | 評価 | 判断 |
| --- | --- | --- |
| 公式crate・任意feature（採用） | 入力バイト列と報告モデルを共有でき、復号層をコピーせずに渡せる。既定ビルドのMSRVを壊さない。CIで両方を検証できる | 採用 |
| MSRVを1.95へ一括引き上げ | 本体全体の要求が上がるが、YARAを使わない利用者に利点がない | 不採用（必要になれば再検討） |
| 外部CLI `yr` を子プロセス実行 | タイムアウト時に強制終了できる利点はある。一方で実行ファイルの入手・ハッシュ固定・更新・起動コスト・出力解析が必要で、未検証の実行ファイルを配布・実行する経路が増える | 不採用（厳格なタイムアウトが必要になった場合の代替候補として残す） |
| 旧版v1.0.0に固定 | MSRVは合うが、修正漏れと脆弱性の追跡が必要 | 不採用（ロードマップ「旧版の安易な固定をしない」） |

## 安全条件（実装で強制）

- **モジュールを組み込まない**：`default-features = false` とし、PE/ELF/.NET/ZIP等のモジュールのパーサーをビルドしない。ルールの `import` は許可リスト（現在は空）以外を拒否する。これにより `rsa`（RUSTSEC-2023-0071）やX.509関連の依存も外れた。
- **テキストルールのみ**：コンパイル済みルールのdeserializeは使わない（上流が危険性を明記）。`include` は無効。
- **ゲート**：コンパイルエラー、警告（エラー扱い）、遅いパターン／ループ、必須メタデータ（`id`・`version`・`severity`・`origin`）の欠落、`id`の重複、台帳（`ledger.json`）にないファイル、サイズ上限超過のいずれかがあれば、ルールセット全体を拒否する（部分的な採用はしない）。
- **結果**：一致はルールID・名前空間・層（`raw` / `decoded/<n>:<方式>`）・層のSHA-256・オフセットと長さだけを記録し、一致したバイト列は保存しない。一致は `yara_rule_match` シグナルとして監査用に出すだけで、削除・隔離・遮断はしない。
- **完全性**：時間予算切れ・タイムアウト・エンジンエラーは `incomplete` にし、「YARAで検出なし」を安全とは扱わない。YARA-Xのタイムアウトは秒単位で即時中断も保証されないため、1ファイルの予算を最大約1秒超える可能性がある（厳格な停止が必要ならCLI隔離を再検討）。

## 依存・ライセンス

- YARA-X本体：BSD-3-Clause。配布物に含める場合は著作権表示と免責の同梱が必要（配布形態は所有者の決定待ち）。
- `cargo deny`：ライセンスは許可リスト内。脆弱性はモジュール無効化後0件。`bincode`（RUSTSEC-2025-0141、**メンテナンス終了、脆弱性ではない**）はYARA-Xのルールのシリアライズにだけ使われ、AegisGuardはその機能を使わないため、理由付きで例外にしている（`deny.toml`）。
- 既定featureのままでは、MSRVフォールバック解決が `time` を脆弱な0.3.45（RUSTSEC-2026-0009）に下げていた。モジュールを外したことで `time` 自体が依存から外れた。**MSRVフォールバックはセキュリティ修正版より古い版を選ぶことがある**ため、依存追加時は必ず `cargo deny` の結果を確認する。

## ルール台帳

`rules/aegisguard/ledger.json` に、ファイルごとの出所とライセンスを記録する。現在のルールはすべて自作（`origin = self-authored`）で、ライセンスはリポジトリ本体と同じ（所有者の決定待ち）。**第三者のルールは、使用・改変・再配布の許諾を1件ずつ確認して台帳に記録するまで追加しない。**
